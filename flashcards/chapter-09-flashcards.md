## Chapter 9: Supply Chain Security II: Static Analysis, SBOM & Signing — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Command to scan a Kubernetes manifest with kubesec and get a risk score? | kubesec scan deployment.yaml — returns JSON with overall score plus `scoring.critical` and `scoring.advise` arrays explaining each point deduction/addition. Exam tip: negative score = fails hardening checks. |
| 2 | cosign command to sign an image with a private key file? | cosign sign --key cosign.key <image>. Requires cosign.key/cosign.pub pair from `cosign generate-key-pair`. Exam tip: signature is stored as a separate OCI artifact in the registry, not embedded in the image layers. |
| 3 | cosign command to verify an image signature against a public key? | cosign verify --key cosign.pub <image>. Exit code 0 = verified. Exam tip: this is what Kyverno's verifyImages rule does internally at admission time. |
| 4 | What two Sigstore services enable 'keyless signing' with `cosign sign` (no --key)? | Fulcio (issues short-lived cert binding OIDC identity to an ephemeral key) and Rekor (immutable transparency log recording the signing event). Exam tip: keyless = identity-based trust, no long-lived private key to manage. |
| 5 | Two common SBOM formats generated by syft? | SPDX and CycloneDX. Command: syft <image> -o spdx-json / -o cyclonedx-json. Exam tip: format choice matters for downstream tooling compatibility (e.g. grype consumes both). |
| 6 | Command to generate an SBOM then scan it for CVEs without re-pulling the image? | syft <image> -o cyclonedx-json > sbom.json && grype sbom:./sbom.json. Exam tip: grype's `sbom:` source reuses the file instead of re-fetching the image. |
| 7 | Kyverno rule type used to enforce image signature verification at admission time? | verifyImages, configured inside a ClusterPolicy with `imageReferences` and `attestors` (public keys or keyless identities). Exam tip: unsigned/failed-verification images are blocked before scheduling. |
| 8 | kubesec vs syft vs cosign — what does each actually check? | kubesec = Kubernetes manifest risk scoring (pod security fields). syft = generates SBOM (package inventory) from an image. cosign = signs/verifies artifact integrity and identity. Exam tip: know which tool answers which exam scenario. |
| 9 | Command to attach a signed attestation (e.g. SBOM or provenance) to an image with cosign? | cosign attest --key cosign.key --predicate sbom.json --type cyclonedx <image>. Exam tip: `attest` embeds a signed in-toto statement referencing a predicate file; `sign` only signs the image itself. |
| 10 | Two Dockerfile static-analysis red flags heavily tested on CKS? | Using a floating `:latest` tag (breaks traceability/reproducibility) and missing `USER` instruction (container runs as root). Exam tip: pin digests/tags and always drop to a non-root USER. |
| 11 | Why pin images by digest (sha256:...) instead of tag in a supply chain security context? | Tags are mutable and can be repointed to different image content; a digest uniquely and immutably identifies the exact bytes. Exam tip: signature verification and chain-of-custody guarantees are only meaningful if the reference can't silently change. |
| 12 | What does Rekor provide in the Sigstore signing workflow? | An immutable, publicly auditable transparency log recording every signing event (certificate + signature), enabling detection of unauthorized or backdated signatures. Exam tip: pairs with Fulcio in keyless cosign signing. |
