## Chapter 6: Microservice Security II: mTLS & Secrets Management — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | Which EncryptionConfiguration provider uses an external KMS plugin (envelope encryption) instead of storing the key locally? | kms (KMSv2). aescbc and secretbox store the encryption key directly in the config file on the control-plane node. Exam tip: kms is the production-recommended choice. |
| 2 | kube-apiserver flag to enable Secrets encryption at rest? | --encryption-provider-config=/path/to/encryptionconfig.yaml. Exam tip: the file and any referenced keys must exist before apiserver starts, and the static pod manifest needs a matching volume mount. |
| 3 | Command to force re-encryption of all existing Secrets after changing EncryptionConfiguration? | kubectl get secrets --all-namespaces -o json \| kubectl replace -f -  Exam tip: a new/changed EncryptionConfiguration only affects objects written AFTER the change; old ones stay as-is until rewritten. |
| 4 | Why are Secrets injected as environment variables considered a vulnerability? | Visible via `kubectl describe pod`, readable from /proc/<pid>/environ by any process with container access, and commonly leaked into logs, core dumps, or child processes. Exam tip: prefer volume mounts. |
| 5 | Do volume-mounted Secrets update automatically when the underlying Secret object changes? | Yes — kubelet syncs the change into the mounted volume within its periodic sync interval. Environment-variable secrets do NOT update without a pod restart. |
| 6 | Which CSI driver integrates external secret stores (Vault, AWS Secrets Manager, Azure Key Vault) with Kubernetes pods? | Secrets Store CSI Driver. Mounts secrets as a volume at pod startup, avoiding storage in etcd. Exam tip: optional secretObjects sync creates a native K8s Secret mirror if needed. |
| 7 | RBAC pattern to restrict read access to one specific named Secret only? | A Role with resourceNames: ["secret-name"] and verbs: ["get"], bound via a namespaced RoleBinding to the target ServiceAccount. Exam trap: resourceNames does not work with 'list' or 'watch'. |
| 8 | What does the 'identity' provider do in EncryptionConfiguration? | No encryption — stores data as plaintext. Exam trap: if 'identity' is listed FIRST in the providers list, encryption is effectively disabled even if other providers are also configured. |
| 9 | Two CKS-tested approaches for pod-to-pod mTLS? | 1) Service mesh sidecar (e.g., Istio PeerAuthentication mode: STRICT) enforcing L7 mTLS. 2) CNI-level transparent encryption (e.g., Cilium WireGuard/IPsec with identity-aware policy). Know both patterns. |
| 10 | Secret rotation strategy when using an external secret store? | Rotate the value in the external store (e.g., Vault); Secrets Store CSI Driver periodically re-syncs and updates the mounted volume. Apps reading the file per-request get the new value automatically; env-var-based apps still need a restart. |
| 11 | How is Kubernetes Secret data stored in etcd by default (no EncryptionConfiguration)? | Base64-encoded, NOT encrypted. Base64 is trivially reversible. Exam trap: candidates often mistake base64 encoding for actual encryption. |
| 12 | What other EncryptionConfiguration providers exist besides kms and identity? | aescbc (AES-CBC, key stored in config file — common exam answer for 'local key' provider), secretbox (XSalsa20-Poly1305), aesgcm (avoid — unsafe key reuse beyond a write-count limit). |
